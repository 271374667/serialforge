# 串口与上位机入门

> 写给那些精通 Qt 界面开发，但此前从未接触过硬件电路板的纯软件工程师。

在纯软件世界里，调一个接口通常意味着发一个 HTTP 请求或者调一个本地函数：有明确的 URL、结构清晰的 JSON，还有标准的 HTTP 状态码告诉你成了还是挂了。

一旦跨入硬件通信的领地，很多初学者会瞬间产生强烈的文化冲击——“为什么没有状态码？为什么连一条消息以什么结尾都要我亲自猜？”

这篇文章帮你建立一张通俗易懂的硬件心智地图。

---

## 两个角色：上位机与下位机

- **上位机（Host）**：就是你正在编写的跑在 PC 电脑上的 Qt 程序。它负责发号施令、绘制漂亮的图形界面、存储数据库。通常来说，上位机算力强大、界面光鲜，而且比较“话多”。
- **下位机（Device / Target）**：插在电脑上的那块嵌入式电路板（单片机、PLC、控制器）。它负责现场真正干活：读温度传感器、开关继电器、驱动电机旋转。

它们之间没有共享内存，也没有 RPC 调用，唯一的桥梁就是一根串口线（或者一条 USB 转串口线）。上位机说一句“把当前气压发给我”，下位机回一句“101.3”。整个通信大厦，就是由这样的一问一答搭建起来的。

---

## 串口到底在传什么？

串口传输的本质，是**一根没有消息边界的流水管道**。

比如你在代码里发出了四个字母 `PING`，在线路上实际上流淌的是 4 个 ASCII 字节：`0x50 0x49 0x4E 0x47`。如果末尾追加了回车换行，还会多出两个字节 `0x0D 0x0A`。

```text
上位机电脑  ───[ P I N G \r \n ]───▶  下位机板子
上位机电脑  ◀───[ P O N G \r \n ]───  下位机板子
```

串口驱动只负责把字节送进操作系统缓冲区。它既不会帮你打标点符号，也不会顺手帮你打包。如果你去读缓冲区，读出来的可能是一整句，也可能是半个字，或者上一条回包的屁股连着下一条回包的脑袋。

这就是为什么必须有**分帧定界**。

---

## 波特率：必须对齐的“说话语速”

波特率（Baudrate）代表每秒钟线路上跑过多少个二进制位（bit）。

常见的波特率有 `9600`、`115200`、`921600` 等。

串口调试最经典的翻车场景是：下位机单片机用 `115200` 的语速滔滔不绝，而你的上位机却用 `9600` 的慢动作去倾听。结果可想而知——上位机读出来的全是一堆类似 `?` 的乱码，或者线路上一片死寂。

**两边波特率必须完全一致，通信才可能成立。**

除了波特率，协议文档里还常常见到一个神秘的代号 **8N1**：
- **8**：8 个数据位（每个字节由 8 个 bit 组成）
- **N**：无奇偶校验位（No parity）
- **1**：1 个停止位（Stop bit）

现代 99% 的设备默认都是 8N1，SerialForge 的默认设置也是它。除非你的硬件特别特立独行，否则不需要改动校验与停止位。

## 帧：如何给一串流水断句

既然串口只给字节流，程序就必须知道“哪几个字节凑在一起算一条完整指令”。

常见的断句规则：
1. **换行符断句（`LINE`）**：最常见。约定每句话说完必须附带 `\r\n`。这就像小学生写作文必须点句号一样。
2. **静默停顿断句（`SILENCE_GAP`）**：常用于一些简陋的工业传感器。设备发完一串报文后，线路会保持一段时间（比如 50 毫秒）没有任何电平变动。上位机发现线路安静下来了，就认定上一句话说完了。
3. **固定长度断句**：每条报文固定 16 个字节，读够 16 个字节就算一帧。
4. **报头标长度**：报文前两个字节写明“后续有 20 个字节”，上位机先读长度，再按需读完内容。

## 物理回显：设备冲你学舌

在某些半双工总线（如 RS-485）或者配置了回显开关的设备上，下位机会把上位机发过去的字节先原封不动回弹一遍，接着再发它真正的响应。

例如：
- 上位机发：`STATUS`
- 上位机收到的实际报文是：`STATUS\r\nSTATUS: RUNNING\r\n`

如果软件没有过滤回显，正则匹配就会直接撞上前半段被弹回来的命令，导致逻辑全盘错乱。在 SerialForge 中，开启 `echo=True` 就能让库自动吃掉弹回来的回显。

## 现场第一次接线排错清单

当你第一次把板子接上电脑，程序却连不上时，顺着这张清单自查：

1. **设备管理器能看到 `COMx` 吗？**
   如果设备管理器没有任何反应，或者黄色感叹号报错，先去装 CH340、CP2102 或 FTDI 的官方 USB 转串口驱动。
2. **端口是不是被其他调试助手占用了？**
   串口是独占设备。如果你电脑后台开着串口助手、PuTTY 或者别的上位机，你的 Python 程序再打开该端口时一定会提示“拒绝访问（Access Denied）”。
3. **TX 和 RX 接反了吗？**
   如果是飞线连接（杜邦线），记住一条铁律：上位机的 TX（发送端）要接到下位机的 RX（接收端），上位机的 RX 要接到下位机的 TX。两边都是 TX 接着 TX，肯定一句话都听不见。
4. **两边共地（GND）了吗？**
   如果两块板子各自独立供电，且地线没有连在一起，电平没有统一参考基准，收到的必然全是一堆火星乱码。
5. **协议要求的换行符对了吗？**
   有些设备只认 `\r\n`（Windows CRLF），有些设备只认 `\n`（Linux LF），有些设备要求末尾带分号 `;`。对照协议手册仔细核对。
