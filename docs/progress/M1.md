## 实际验证

以下命令均在 Windows 11 开发机运行并成功：

```text
uv sync
uv run ty check --python-version 3.11 --python-platform win32 tests/typing/qt_smoke.py
uv run ty check --error all tests/typing/qt_smoke.py
uv run ty check
uv run ruff check src tests scripts
uv run ruff format --check src tests scripts
uv run pytest                         # 16 passed
uv run pylint src                     # 10.00/10
uv build                              # wheel + sdist
uv run twine check dist/*             # PASSED（由 ci.py 过滤非发行物）
uv run python scripts/ci.py --fast
uv run python scripts/ci.py           # 全量通过
```

ty 的 `check --help` 明确支持 `--python-version`、`--python-platform` 与
`--error all`。Qt smoke 覆盖 `Signal`、`.connect`、`.emit`、`@Slot`、
`QThread.run` 和 `result.spec is X`；在 `all = "error"` 配置与显式命令行模式下均无诊断。

## 假设与偏差

- M1 只提供 `SerialHandler`、`DeviceFinder` 和 testing 的可导入空壳；真实串口、调度、探测、日志和重连按 M2-M6 实现。
- `FramingConfig` 的字段按设计中的四种模式和长度/校验需求提供起始骨架，具体帧算法留在 M2。
- 设计要求的 `ProbeSpec` 与 `RuntimeConfig` 通过延迟导入保持定义层无循环依赖；这不改变公开导入路径。
- 用户级 `project-ai-normalize` 的 `scaffold.py`、git hook 和部分规则文件含冲突标记，无法执行；项目内规范结构依据同一模板手动落地，并清理了复制到项目内的冲突文件。

## 未验证项

- **未在真实串口硬件验证**：读写线程、Windows 计时粒度、DTR/RTS 脉冲、拔线、USB 芯片差异、Windows 10。
- 尚未验证跨 Qt 工作线程排队信号在依赖下限版本上的对象身份；M1 只验证 ty 静态识别。
