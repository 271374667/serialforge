## 最终顶层名单

`SerialForge, Spec, Message, MessageCategory, DeviceInfo, CommandStatus, ConnectionState, ResponseMode, Correlation, ScanMode, SerialForgeError`。

SpecRole、CommandCall 具名类型及 DeviceProfile/DeviceFinder/LogConfig/底层配置放 advanced；异常子类放 errors。Spec 实例角色仍可以直接读取，不要求用户导入 SpecRole 才能使用门面。

## 过渡期的明确名单

过渡期只保留一轮旧名字：现有 15 个名字 + SerialForge/Spec/Message/MessageCategory，共 19 个。以下八个最终不在顶层的旧名字属于兼容入口：SerialHandler、DeviceFinder、DeviceProfile、CommandSpec、EventSpec、LogConfig、CommandResult、DeviceEvent。下一次明确移除兼容入口时再收敛为 11 个，移除版本另行由用户决定，本轮不发布。

- CommandSpec/EventSpec 使用兼容构造形状保留 frozen/eq=False 和实例身份，注册时不转成第二个 Spec；旧自动推断仅限旧构造器。
- 旧结果类可保留构造/导入，不承诺新返回值仍满足旧 isinstance。内部只保存一个最终 Message，不为兼容观察者发两份完成对象。
- SerialHandler 仅保留旧 profile 构造入口与 register/unregister/send/send_and_wait 名称桥接；主线程要求和新失败异常语义明确属于迁移变化，不伪称全行为兼容。
- SerialForge 与兼容 SerialHandler 都不暴露 command_finished/event_received/error_occurred/traffic_logged；旧消费者改用 received/raw_sent/result/check_errors。
- 日常文档只展示新 API，兼容名单放迁移章节。DeviceFinder 的旧进阶入口不成为新的日常扫描要求；新门面 scan 无完成/进度信号。
- 值字段不再用 None；默认 result_type=str，命名组字典显式 dict；count=-1、parser=""；同步失败改为 raise，异步失败从 result() 重抛。

## 例外与风险

本轮用户明确要求字段重载和 context 字典，因此 Spec/add/configure/scan 可超过规则 03 的五参数限制，params/context 可用 Mapping；业务层仍不得随意使用无结构字典跨模块。parser="" 的 union 如实标注，不能用不真实的类型注解隐藏哨兵。

received 中 RAW_RECEIVE/解析帧/COMMAND_RESULT 可能源自同一物理响应，日志只过滤 RAW_RECEIVE；本地失败终态不虚构设备 RX 字节。raw_sent 为确认写入的 bytes，没有端口字段，扫描多端口精确日志归属不在裸 bytes 能力范围内。

“超时不回调 + 无错误信号”意味着仅注册成功闭包无法取得失败；应用需读取 result/check_errors。主线程堵塞超过截止时间时结果仍可成功，但闭包不再执行。
