# 0004_阻塞连接与可选USB身份契约

> 分类: knowledge/software  |  创建: 2026-10-08  |  适用范围: serialforge 0.0.1 的连接、搜索和缓存
> 关键词: 阻塞、线程池、可选 VID/PID、FIRST_MATCH、ALL、取消、缓存

## 结论（先给做法，再讲原理）

- 2026-10-08 用户明确要求：连接和搜索对调用方阻塞，内部使用多线程，完成后才返回；异步由使用方自行开线程。
- 用户追加：VID/PID 可省略，只需波特率候选与探测指令；提供 VID/PID 时优先筛选和利用设备身份缓存。
- 这两条覆盖原 v10 的异步 connect/find_async 与 VID/PID 非空条款，其余第 7 章的探测规则继续生效。

## 背景

旧 connect 启动 QThread 后立即返回，控制台示例为了顺序演示自行写 _wait_until/processEvents。
最新契约要求 connect 的就绪等待由库承担；不能依赖主线程的 Qt 信号送达或事件循环来解除等待。
因此使用线程 Event 完成握手，发现、打开和初始化均在工作线程完成。

## 细节

| 接口 / 配置 | 当前行为 |
| --- | --- |
| `DeviceProfile(baudrates=[...], probe=...)` | 不要求 VID/PID；默认扫描全部可用串口，以有效探测回复确认设备 |
| `vid_pid=None` / 空序列 | 不做 USB 白名单过滤，构造后规范化为空 tuple |
| 非空 `vid_pid` | 自动发现只探测名单内串口；原三参数位置调用保持兼容 |
| `find(ScanMode.ALL)` | 内部并行探测所有候选端口，返回全部成功设备；每个成功端口停止后续波特率 |
| `find(ScanMode.FIRST_MATCH)` | 返回先完成的成功者，取消其他探测、关闭句柄、等待线程退出，最多一个结果 |
| `connect()` | 内部固定 FIRST_MATCH；阻塞直到打开和初始化完成，返回后可立即发送 |
| `connect("COM11")` | 信任指定端口，绕过 VID/PID 过滤，仍探测波特率和回复 |
| `connect(DeviceInfo)` | 直接打开；缺少波特率时取 profile 第一候选 |
| 首次连接失败 / 取消 | 资源回收完成后同步抛 SerialForgeError 子类；状态/错误信号仍保留 |
| `probe_pool_size` / `probe_total_timeout_s` | 保持默认 4 / 30 秒，可由 RuntimeConfig 覆盖 |

同一端口串行尝试候选波特率，不能同时打开两个不同波特率的句柄。
缓存只调整候选列表顺序，仍验证探测回复；不在候选列表中的缓存值不参与尝试。
缓存键保留现有 USB 序列号/位置格式；无 USB 身份时依次用序列号、位置、大小写归一的端口名。
没有稳定身份时，端口号变化会丢失原缓存关联，这是回退到端口名的实际边界。

send 的非阻塞语义、命令结果和事件信号、自动重连策略沿用原设计。
连接/搜索本身无需事件泵；普通 Qt 跨线程信号的接收仍由使用方提供事件循环。

## 常见改动点

- 改阻塞连接：connection/serial_handler.py:connect 与 connection_worker.py 的就绪握手；不能先发布成功再完成初始化。
- 改搜索模式：discovery/device_finder.py:_scan；返回前必须等待取消任务回收句柄。
- 改身份输入：models.py:DeviceProfile 与 discovery/port_scanner.py:scan；空名单必须允许非 USB 端口。
- 改缓存身份：discovery/baud_cache.py:key；保持已有 USB 缓存键兼容。
- 公开 README/docs 尚有旧异步表述；按规则 02 §11，等待用户明确要求更新公开说明时同步，勿将旧说明当成当前契约。
