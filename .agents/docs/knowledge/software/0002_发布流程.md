# 0002_发布流程

> 分类: knowledge/software  |  创建: 2026-10-08  |  适用范围: 维护者在本机把 serialforge 发布到 TestPyPI / PyPI
> 关键词: 发布 release uv version uv build twine check scripts/release.py TestPyPI 令牌

## 结论（先给做法，再讲原理）

- 发布只能由维护者在本地 Windows 10/11 x64 环境执行；AI 不执行上传、推送或打 tag，
  `scripts/release.py` 默认只做 dry-run。
- 顺序固定：工作区干净 → `uv run python scripts/ci.py --release` 全绿 → `uv version --bump` →
  `uv build --out-dir outputs/01_dist` → `twine check` → TestPyPI 安装验收 → 人工 `--publish --target pypi`。
- 令牌只从 `UV_PUBLISH_TOKEN` 或系统 keyring 读取，不写入仓库、参数或日志。

## 背景

适用版本 0.0.1。项目不采用 Trusted Publishing 或云端 CI，也不创建 tag；上传是整条链路上
唯一不可逆的步骤，因此流程把它隔离成最后一个需要人工输入口令的显式命令。

## 细节

### 发布前检查

```powershell
uv sync --locked
uv run python scripts/ci.py --release
```

这一步覆盖单版本全量测试、Ruff、ty、pylint、构建、`twine check`、wheel 干净环境冒烟、
Python 3.11–3.14 矩阵和最低直接依赖检查。`--release` 使用独立的 `UV_PROJECT_ENVIRONMENT`
目录，不应修改已提交的 `uv.lock`。

确认工作区干净后再修改版本：

```powershell
uv version --bump patch
uv sync
uv run python scripts/ci.py --release
```

### 构建与检查

构建物统一写入 `outputs/01_dist/`：

```powershell
uv build --out-dir outputs/01_dist --clear
uv run twine check outputs/01_dist/serialforge-0.0.1-py3-none-any.whl outputs/01_dist/serialforge-0.0.1.tar.gz
```

不要把 `dist/`、`build/`、wheel、sdist 或日志提交到 Git。构建后可把 wheel 拷贝到项目
目录之外，用 `uv run --isolated` 或另一台机器安装并运行：

```powershell
uv run python scripts/ci.py --smoke --wheel outputs/01_dist/serialforge-0.0.1-py3-none-any.whl
```

### 发布脚本

```powershell
uv run python scripts/release.py
```

提交经过检查的版本、文档和锁文件变更，确保工作区干净后运行脚本。默认模式运行完整
发布前 CI，检查工作区及构建物，不访问上传接口；如工作区有改动会直接失败。

真正发布必须由维护者在交互终端显式执行 `--publish --target testpypi`，输入
`publish testpypi`；在 TestPyPI 安装验收后，再人工执行 `--publish --target pypi`，输入
`publish pypi`。默认目标是 TestPyPI。传输令牌由 uv 从 `UV_PUBLISH_TOKEN` 或系统 keyring
读取，不写入仓库、参数或日志；TestPyPI 和 PyPI 使用各自的账户与令牌。

本项目规则禁止 AI 执行 `scripts/release.py --publish`、`uv publish`、`git push` 或创建 tag。

### TestPyPI 安装验证

在仓库外执行。从 TestPyPI 目标版本的文件列表取得 wheel 的完整 HTTPS 下载 URL
（`test-files.pythonhosted.org`），替换下面的占位符：

```powershell
uv run --no-project --isolated --python 3.11 --with "<TestPyPI wheel 的完整 HTTPS URL>" --default-index https://pypi.org/simple python -c "from importlib.metadata import version; import serialforge; print(version('serialforge'), serialforge.__file__)"
```

核对版本和安装位置，然后用本仓库的外置 Demo 和测试做验收。直接指定目标 wheel，
运行依赖从 PyPI 获取；不要混用两个索引搜索 serialforge，避免选到 PyPI 的同名版本
或 TestPyPI 上不完整的依赖。已用过的 PyPI 版本不能重传；首次上传后改用项目范围
令牌。

## 常见改动点

- 想改发布目标、口令或 dry-run 行为 → 改 `scripts/release.py`，并保留"非交互环境拒绝上传"的回归测试。
- 想改产物路径 → 同时改本文件与 `scripts/release.py`，构建输出一律落在 `outputs/01_dist/`（见 `rules/13`）。
- 想改版本号 → 用 `uv version --bump`，不要手改多处；版本必须回到 `uv.lock` 与 `CHANGELOG.md`。
