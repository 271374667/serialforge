# 0003_PySide6 6.5.0 的 connect 名称冲突

> 分类: questions | 发现: 2026-10-08 | 状态: 待修复 | 严重级别: 高

## 现象

Python 3.11.12 x64、PySide6-Essentials 6.5.0、pyserial 3.5、loguru 0.7.0 下，
`handler.command_finished.connect(slot)` 抛出
`TypeError: SerialHandler.connect() takes from 1 to 2 positional arguments but 4 were given`。
最低组合套件结果为 14 失败、84 通过、1 硬件跳过；Demo 和 send_and_wait 均受影响。

## 复现步骤

运行 `scripts/ci.py` 的最低依赖阶段，或在 6.5.0 环境中声明 QObject 子类，同时定义
Signal 和业务 connect 方法，再调用 signal.connect(slot)。

## 排查过程

- 常规 Python 3.11–3.14 矩阵使用锁定的 PySide6-Essentials 6.11.2，全部通过。
- 固定开发工具之后，lowest-direct 实际选中 6.5.0，首次暴露此问题。
- 正在用独立 Python 3.11 环境验证后续发行物，依赖下限必须由完整套件实测决定。
- 6.5.1.1 的 QObject/Signal 最小复现同样失败，不能作为替代下限。

## 根本原因

旧版 PySide6 的信号连接会调用发送对象的 connect 属性，与 SerialHandler 的公共
设备连接方法发生名称冲突。单凭可安装 wheel 或较新依赖下的测试无法证明最低版本兼容。

## 修复方案

保留设计规定的 connect API；验证兼容版本后提高 PySide6-Essentials 的依赖下限。
当前尚未确定通过完整套件的最低组合，不能宣称此问题已修复。

## 如何避免再犯

- 发布前固定开发工具并实际运行最低运行依赖套件，包括 Demo 和信号连接。
- 记录 Python、Qt 绑定和 pyserial/loguru 的准确版本，不以声明范围代替兼容性证据。
