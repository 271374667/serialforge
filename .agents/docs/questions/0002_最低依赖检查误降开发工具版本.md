# 0002_最低依赖检查误降开发工具版本

> 分类: questions | 发现: 2026-10-08 | 状态: 已修复 | 严重级别: 中

## 现象

M7 发布前 CI 的 Python 矩阵通过，但最低依赖解析选中 `pylint==0.15.2`，构建时因
`except OSError, ex` 的 Python 2 语法失败，尚未执行库的最低运行依赖测试。

## 复现步骤

在包含未固定开发工具的项目副本中运行 `uv sync --resolution lowest-direct`。

## 排查过程

- uv 的 lowest-direct 同时降低 project dependencies 和 dependency-groups.dev。
- pylint、pytest、ruff 等开发工具没有下限，解析到了不支持当前 Python 的旧发行物。
- 单纯 `--no-dev` 只改变安装选择，不能作为开发组不参与解析的保证。

## 根本原因

运行依赖下限验收混入了开发工具下限，导致测试环境先于被测库失败。

## 修复方案

`e3fab0c` 从仓库 `uv.lock` 的 dev 组读取锁定版本，向临时副本的 `uv.toml` 写入
constraint-dependencies；运行依赖保持 lowest-direct，仓库配置和锁文件不变。
回归测试确认开发工具被固定，pyserial 等运行依赖不被这些约束固定。

## 如何避免再犯

- 验证运行依赖下限时固定开发工具，并打印实际安装的运行依赖版本。
- 在临时项目中解析，验收结束核对仓库 `uv.lock` 的哈希和 Git diff。
- 完整结果记录到 M7 checkpoint，不能把解析成功视为测试通过。
