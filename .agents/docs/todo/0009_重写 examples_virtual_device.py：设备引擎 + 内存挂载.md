## 背景

用户对现有文档与示例全部不满意，本任务序列的第一项是 `examples/virtual_device.py`。现存问题：

1. 设备侧细节泄漏给使用方（`use()` / `inject_alarm()` / `silent` / `port="SIM-DEVICE"`），不满足"使用方只需要知道指令和返回值"。
2. 指令集能力不足：没有周期性主动上报（只有手工注入一次 `ALARM`），没有"发一条后持续返回、直到发下一条才停"的流（`MONITOR` 现在只是固定 4 帧），没有失败路径（`DEVICE_ERROR`）与 `until` 形态。
3. 设备行为没有状态机：不认识自身状态（空闲 / 流式 / 上报中），无法演示"下一条命令改变设备行为"。

路线决策（`.agents/docs/explore/0002_Windows虚拟串口与设备端方案调研.md`）：**先做内存引擎，不装任何内核驱动**；
真 COM 口（com0com 端口对）留作后续挂载方式，引擎与传输解耦以便复用。
