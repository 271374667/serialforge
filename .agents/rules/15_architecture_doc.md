# 15 · 架构总览文档（.agents/ARCHITECTURE.md）

每次会话**无条件必读** `.agents/ARCHITECTURE.md` 的**必读区**；结构或形态变化时更新它；
**发现它与代码不符时当场修正**。

## 1. 定位：它是活文档，不是归档件

`.agents/ARCHITECTURE.md` 是项目的架构总览——一份让新会话**不读代码就能接手**的地图。
它的性质与 `.agents/docs/**` 完全不同：

| 性质 | `ARCHITECTURE.md` | `docs/**` 下的文档 |
| --- | --- | --- |
| 编号 | **不编号**，固定文件名 | `NNNN_*.md` |
| 归档 | **不归档**，永远原地更新 | 过时移入 `_archive/` |
| 读取 | 必读区**每次会话无条件读** | 按需加载 |

原因：它被 `AGENTS.md` **硬引用**为架构的唯一真源，一旦编号或归档，引用就会漂移或断链。
新鲜度不靠编号版本表达，靠**文首的基线 commit + 文末的变更日志表**。

**为什么放在 `.agents/` 根下**：

- 不放 `docs/knowledge/`——那里是编号归档体系，且定位是"精华、宁缺毋滥"；总览是必读基础设施，不该跟精华混在一起；
- 不放项目根目录——根目录白名单只有 `AGENTS.md` / `README.md` / `pyproject.toml` 等，且这份主要给 AI 读，放根目录等于跟 `AGENTS.md` 抢入口；
- 不放 `.agents/docs/` 下——会破坏"docs 下一切皆 `NNNN_*.md`"的约定（`04_docs_system.md` §2）。

## 2. 读取纪律：分区读，不要整份读

文档切成两半，**必读区有上限、按需区没有**：

| 区 | 小节 | 什么时候读 | 上限 |
| --- | --- | --- | --- |
| **必读区** | ① 项目是干什么的 ② 外部形态 ③ 模块地图 ⑥ 关键不变量 | **每次会话，无条件** | **≤150 行**（约 3–5K tokens） |
| **按需区** | ④ 交互关系 ⑤ 状态与外部边界 ⑦ 深潜入口 ⑧ 变更日志 | 要动结构 / 要交接 / 要深入某模块 / 要查变更史 | 不设上限 |

```
1) 读 AGENTS.md
2) 读 .agents/ARCHITECTURE.md 的必读区（第 1、2、3、6 节）   ← 无条件
3) 按 AGENTS.md 第 2 节索引，只读本次任务需要的 rules
4) 扫一眼 .agents/docs/todo/ 与关联 checkpoint/
```

**为什么必须分区**：总览是唯一无条件必读的文件，读它取代的是"翻目录树 + 读源文件猜职责"的
探索成本——省 token 的关键在于**不猜错**。但对小任务（改个参数、修个 bug）来说，
整份读完是纯亏。必读区只留"去哪改、不能碰什么"，把成本钉死在 150 行以内；
交互图、外部边界这类"要动结构才用得上"的内容放进按需区，写多长都无所谓。

**必读区超了 150 行怎么办**：不外删内容，而是**外移**——把细节搬去
`knowledge/software/NNNN_*.md`，必读区只留一句结论 + 路径指针。
**这条不是自觉，是硬校验**：`newdoc.py check` 会数必读区实际行数，超 150 直接报问题；
`AGENTS.md`（≤250 行）与 `rules/01`（≤200 行）同样在固定成本审计范围内（见 `04` §8）。

## 3. 内容门槛：三问

写每一段之前过三问：

1. 不写这一段，新会话会不会**做错决定**？（会 → 写）
2. 不写这一段，新会话要不要**重新翻代码**才知道？（要 → 写）
3. 这件事**看代码一眼就明白**吗？（是 → 不写；写了就是每次会话都在烧 token）

**不该出现在这里的**：

- 完整的类/函数清单、逐文件说明——那是代码与 docstring 的事；
- 详细流程与参数说明——搬去 `knowledge/software/NNNN_*.md`，这里只留一行索引；
- 当前进度与在途任务——那是 checkpoint / todo；
- bug 复盘——那是 questions；
- 变更流水——只留第 8 节那张一行一条的表格。

## 5. 第 6 节「关键不变量」该写什么

**定义**：改动任何代码时都不能破坏的约定。它通常有三个特征——
① 散落在代码各处，没有单一位置写着；
② 违反了不会立刻报错，而是悄悄产出错数据或埋雷；
③ 换个 AI 会话来改，很容易无意中打破。

**写法**：一条一行，格式固定为「约束 + 违反后果 + 生效范围」。

```
- 一切落盘先写 `*.tmp` 再原子替换 —— 违反：写入中途崩溃会损坏用户文件 —— 生效：`infra/storage/`
- 二进制格式（PMX / VMD / VPD）必须 round-trip 一致 —— 违反：用户数据静默损坏 —— 生效：`infra/formats/`
- 所有解析器经工厂注册表取用，禁止外层 `isinstance` 分派 —— 违反：新增格式要改 N 处调用点
- 金额字段一律 `Decimal`，禁止 `float` —— 违反：累计误差导致对账不平
- 公开数据格式的字段只增不删 —— 违反：老版本存档读不进来
```

**写不出来怎么办**：先写「已知的坑」，不要空着——空着等于告诉下一个会话"这个项目没有约束"。

## 6. 什么时候更新（五个节点）

| # | 节点 | 说明 |
| --- | --- | --- |
| ① | **会话交接** | 与写 checkpoint 同一节点——**先更新总览，再写交接快照** |
| ② | **阶段 / 里程碑任务完成** | 与 checkpoint 归档检查点②同一节点，顺手做，不额外开流程 |
| ③ | **结构发生变化** | 模块增删改、目录调整、依赖方向变化、对外接口变化（CLI 参数 / API / 数据格式） |
| ④ | **形态发生变化** | 引入或移除第三方依赖、运行方式变化、交付方式变化 |
| ⑤ | **发现不符（随时）** | 干活时发现文档与代码对不上——**当场改**，不必等上面四个节点 |

**节点⑤ 是防腐化的关键**。活文档最怕的不是写得差，而是**过时**：
一份描述着已不存在的架构的地图，比没有地图更危险——没有地图你会去查，有地图你会信。
发现即改的成本极低（反正已经看见了），却是唯一能防住腐化的机制。

**不更新**：bug 修复、小功能迭代、未改变模块职责与依赖关系的重构——但每次收尾要过一眼确认。

**更新动作**（三步，缺一不可）：

1. 改正文对应小节；
2. 更新文首 `最后更新` 与 `基线 commit`；
3. 在第 8 节变更日志表**顶部**加一行 → 随本节点的 commit 一起提交。

## 7. 与其余文档的分工

| 想知道 | 读哪里 |
| --- | --- |
| 项目全貌、模块职责、关键不变量 | **`.agents/ARCHITECTURE.md` 必读区**（每次会话读） |
| 交互细节、外部边界、深入某模块 | `ARCHITECTURE.md` 按需区 + `knowledge/software/NNNN_*.md` |
| 为什么踩过这个坑、怎么修的 | `.agents/docs/questions/` |
| 现在做到哪、下一步做什么 | `.agents/docs/checkpoint/`、`.agents/docs/todo/` |
| 硬约束与流程细则 | `AGENTS.md` + `.agents/rules/**` |

**架构决策的留痕位置不变**（`03_architecture.md` §7）：非直觉的架构选择，
代码里用 docstring `Note:` 说明一句，理由展开写进 `knowledge/software/NNNN_*.md`；
总览只在第 3、4 节体现**结论**，不复制论证过程。

## 8. 小项目用精简形态

**判据（满足任一即为小项目）**：模块 / 目录 **< 5 个**；一次性或短命项目（没有"新会话"场景）；
结构仍在剧烈变动的早期项目。

小项目**不是不生成**，而是生成**精简版**——只保留必读区（第 1、2、3、6 节），去掉按需区
（第 4、5、7、8 节），文首标注 `> 形态: 精简`。好处：路径稳定、`AGENTS.md` 引用不断链、
`newdoc.py check` 能识别；等项目长大（模块数超阈值或开始跨会话）再补全 4、5、7、8 节，
把标记改回 `形态: 完整`。

生成方式：`scaffold.py --lean-arch`。判定权在 AI——拿不准就问用户一句。

## 9. 规范化存量项目时怎么生成它

1. **先扫**：`README.md` / 包配置（`pyproject.toml` 等）/ 入口文件 / 目录树 / import 关系图
   （用 `Grep` 找类定义与 import，大项目用 Explore 子代理扫，**别把整个代码库读进主上下文**）。
2. **再问**：扫不出来的（项目目标、背景动因、边界、历史包袱）**一次性问完用户**，不要分批问。
3. **判形态**：按 §8 判据决定完整版还是精简版。
4. **迁移优先**：项目里已有 `架构.md` / `docs/design/` → **整份搬过来裁剪**，
   不要照模板重写（第 10 条迁移纪律：存量文件的价值通常高于新模板）。
5. **落盘**：`scripts/scaffold.py` 生成空壳后填充内容，跑 `newdoc.py check` 校验。

**存量项目红线（2026-09-08 起）**：本节流程对**一切被规范化的项目**生效——
迁移优先只决定内容来源（整份搬存量文档裁剪），**不等于免生成**；
项目里已有旧 `AGENTS.md` 导致脚手架提示跳过入口时，其余结构（含本文件的空壳）照常生成，
收尾时 `.agents/ARCHITECTURE.md` 必须存在且必读区已填，缺失即本次规范化未完成。
