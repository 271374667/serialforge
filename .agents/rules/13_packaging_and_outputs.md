# 13 · 打包、版本与输出目录

打包、发布、处理构建产物、引入二进制文件前读本文件。

## 1. 打包三要素（缺一不可）

打包（产出可执行 / 可安装物）之前，必须先明确三件事，缺任何一件不许动手：

1. **入口文件**：程序从哪里启动（`main.py` / CLI 入口函数 / GUI 主窗口模块），
   **写死在打包脚本里**，不许每次口述或临时找。
2. **版本号**：来自全局常量位置（见 §2），不现场编。
3. **打包脚本**：打包必须落成**可重复执行的脚本**（`scripts/build_xxx.py` / `.bat` / `.ps1`），
   **用户自己也能一键运行**。**禁止每次由 AI 临时拼命令打包**——
   打包方式一旦确定就固化成脚本。

## 2. 全局常量与 `__version__`

- 项目要有一个**存放全局常量的模块**（如 `constants.py`、`_version.py`），
  集中放 `__version__` 等全局常量，避免版本号散落在多个文件里。
- `__version__` 必须是**单一真源**：打包配置（pyproject / setup / 打包脚本）从它读取或同步；
  两处手写时必须有一致性检查，防止漂移。
- **版本号必须出现在软件里**，让用户看得到自己在用哪一版：

| 形态 | 要求 |
| --- | --- |
| GUI 程序 | **标题栏**显示版本（如 `我的工具 v1.2.3`） |
| 命令行程序 | `--version` 参数 + 启动横幅 / 帮助信息中显示 |
| Python 库 | `__init__.py` 导出 `__version__` |

## 3. 输出目录 `outputs/`（根目录只留一个出口）

**所有构建与运行输出统一放根目录 `outputs/` 下**：

```text
outputs/
├── 01_dist/           # 打包产物（替代根目录 dist/）
├── 02_build/          # 构建中间产物（替代根目录 build/）——留在这里，构建工具会回读做增量构建
└── 03_运行输出/        # 软件运行产生的输出：正式结果、需留档但用户不一定来取的文件
                       #（子文件夹名说明里面是什么，如「软件输出」「批量导出」）
```

- **`outputs/` 的判据是「产物 vs 消耗品」，不是「是否交付」**（2026-09-12 定）：
  只要是**程序的正式产出**就进 `outputs/`——包括**用户不会主动来取、但也不该随手删**的结果
  （例：批量跑出 300 张图、用户只挑走 5 张，剩下 295 张仍然进 `outputs/03_运行输出/`）。
  理由：这类文件有留档价值，放进 `temp/` 会被「用完即删」的清理逻辑误删。
  真正属于 `temp/` 的只有**试验、排查用的一次性东西**（判据见 `rules/08` §4.1）。
- **`02_build/` 留在 `outputs/`**（2026-09-12 定）：构建中间产物看着「生成后不再回读」，
  但**构建工具会回读它做增量构建**，所以不属于「不再回读的一次性产物」；且它与 `01_dist/`
  同源、便于一起排查。**不并入 `temp/`。**
- **工具自管缓存既不进 `outputs/` 也不进 `temp/`**：`__pycache__`、`.pytest_cache`、
  `.ruff_cache`、`.mypy_cache`、`.venv` 等由工具自己决定位置与生命周期，**留在原地**即可——
  `outputs/` 与 `temp/` 只装「我们自己的东西」。
- **禁止直接在 `outputs/` 根下放任何文件**，一律进子文件夹，
  子文件夹名说明里面是什么（是软件输出就建「软件输出」子文件夹，以此类推）。
- `dist/`、`build/` **不再出现在项目根目录**；打包脚本里的输出路径写
  `outputs/01_dist/` 等子目录。
- `outputs/` 整体加入 `.gitignore`。
- **与 `temp/` 的区别（一句话）**：`outputs/` 装**产物**——删了要重新构建或重跑；
  `temp/` 装**消耗品**——删了无影响，程序应当能自己重建。

## 4. 二进制依赖 `bin/`

- 项目依赖的 exe / dll 等二进制文件，放根目录 **`bin/`**，
  并在说明文档或 knowledge 里记录**来源与版本**。
- **没有二进制依赖就不要创建 `bin/`** —— 根目录保持简洁。
- `bin/` 下大文件（>100MB）按 `rules/08` §6 链接处理；
  是否进 Git 由许可证与体积决定，默认问用户。

> 说明类文档（README 等）的更新纪律见 `rules/02` §11。
