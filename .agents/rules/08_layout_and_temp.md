# 08 · 目录布局与临时文件

新建目录、新增配置文件、产生临时产物、处理大文件前读本文件。

## 1. 根目录洁癖

根目录空间宝贵，**只保留约定的少量文件**（`AGENTS.md`、`README.md`、`pyproject.toml`、
`uv.lock`、`.gitignore`、CI 配置等）。新东西一律进子目录：

| 内容 | 位置 |
| --- | --- |
| 源码 | `src/` |
| 测试 | `tests/` |
| 依赖 / 第三方资源 | `dependence/` |
| **二进制依赖（exe / dll）** | `bin/`（**没有就不创建**，见 `13_packaging_and_outputs.md` §4） |
| **构建与运行输出（产物）** | `outputs/`（dist/build 与程序正式产出收敛于此；判据是「产物 vs 消耗品」，见 `13_packaging_and_outputs.md` §3） |
| **配置文件（toml / json / yaml / ini …）** | `config/`（配置集中地，见 §3） |
| **运行时数据（数据库 / 状态文件 / 缓存）** | `data/`（程序自己写的运行数据，见 §4） |
| 临时产物（消耗品） | `temp/`（用完即删，见 §5） |
| 规范与文档 | `.agents/` |

**禁止**：在根目录直接扔 `test.py`、`调试.py`、`output.txt`、`新建文件夹/` 之类无归属的杂物；
**禁止**把配置文件散落在根目录或 `src/` 下（统一进 `config/`，见 §3）；
**禁止**把数据库与运行时状态文件（`*.db`、`*.sqlite3`、`state.json`、`last_task.json` 等）
直接放在项目根目录（统一进 `data/`，见 §4）。

## 2. 新项目标准骨架

```
<project>/
├── AGENTS.md
├── README.md
├── pyproject.toml
├── uv.lock
├── .gitignore
├── src/<package>/
├── tests/
├── dependence/        # 项目自带依赖、预编译库、外部资源
├── bin/               # 二进制依赖（exe/dll），没有就不创建
├── outputs/           # 构建与运行输出（dist/build/正式产物），根下不直接放文件
├── config/            # 配置文件集中地（toml/json/yaml/ini + 模板），见 §3
├── data/              # 运行时数据：数据库、状态文件、缓存，见 §4（默认 .gitignore）
├── temp/              # 临时工作区
└── .agents/
```

已有项目按需向该结构靠拢，**不要为了对齐而大规模搬迁**，先提方案再动。

## 3. 配置文件集中地 `config/`（唯一指定位置）

**所有「给人配置、人会去改」的配置文件，统一放在项目根目录的 `config/` 下。**
这个目录就是**指定的、集中放置配置文件的唯一地点**，不再散落到根目录、`src/` 或各功能模块旁边。

**覆盖范围**（全部进 `config/`）：

| 类型 | 示例 |
| --- | --- |
| TOML | `config/settings.toml`、`config/app.toml` |
| JSON / YAML | `config/settings.json`、`config/pipeline.yaml` |
| INI / CFG | `config/app.ini`、`config/logging.cfg` |
| 环境变量模板 | `config/.env.example` |
| **配置模板** | `config/*.example.toml`、`config/template/xxx.toml` |
| 环境/机器相关覆盖 | `config/*.local.toml`（不进版本控制） |

**例外（必须留在根目录，不算违规）**：由工具链、打包后端或平台**强制指定位置**的元数据文件——
`pyproject.toml`、`uv.lock`、`.gitignore`、`.editorconfig`、CI 配置（`.github/workflows/*.yml`）、
工具自身配置（`ruff.toml`、`.pre-commit-config.yaml`、`package.json` 等）。

> **判据一句话**：**挪走就会让工具找不到、构建或运行失败 → 留根目录；给用户或程序读的 → 进 `config/`。**

**目录约定**

```
config/
├── settings.toml          # 主配置（含默认值，可直接提交）
├── settings.example.toml  # 模板：进版本控制，不含密钥
├── settings.local.toml    # 本地覆盖：进 .gitignore，只在自己机器上存在
├── app.ini
└── template/              # 同一类配置有多份模板/多环境时按用途分组
    ├── dev.toml
    └── prod.toml
```

- `config/` **随仓库提交**（默认配置与模板要能跟着代码分发）。
- **敏感信息**（密钥、令牌、账号）与**机器相关路径**只出现在 `*.local.*` 里并加入 `.gitignore`；
  仓库里只留 `*.example.*` 模板。**绝不允许**把真实密钥提交进 `config/`。
- 代码读取配置时用 `pathlib` 从项目根定位（如 `PROJECT_ROOT / "config" / "settings.toml"`），
  **不要**硬编码绝对路径或盘符（见 §7）；打包发布时确认 `config/` 随包分发（见 `13_packaging_and_outputs.md`）。
- **新增配置前先看 `config/` 里有没有同类文件**：能合并进现有文件就合并，别一个用途开一个新文件。
- **存量项目**已有的散落配置文件**不强制搬迁**（搬迁属独立变更，先提方案、确认范围后再动，见 §2 末）；
  **新加的配置一律进 `config/`**。

## 4. 运行时数据目录 `data/`（程序自己写的都进这里）

**程序运行过程中产生或需要、但不是交付产物**的数据，一律放项目根目录的 `data/` 下。
判据是「谁在读写」：**程序自己读写的是运行数据 → `data/`**。

**覆盖范围**

| 类型 | 示例 |
| --- | --- |
| 数据库 | `data/app.db`、`data/cache.sqlite3` |
| 任务 / 进度状态 | `data/last_task.json`、`data/state.json`、`data/progress.json` |
| **凭证 / 会话缓存（带有效期）** | `data/cookies.json`（爬虫 30 分钟有效的那份）、`data/session.json`、`data/token.json` |
| **UI 记忆配置** | 窗口尺寸与位置、上次打开的目录、列宽排序、主题记忆等界面状态 |
| 缓存 / 索引 | `data/cache/`、`data/index/` |
| 运行历史与日志 | `data/history.json`、`data/logs/` |

**四个目录的分工（别放错）**

| 目录 | 装什么 | 谁写 | **程序会回读吗** | 进版本控制 |
| --- | --- | --- | --- | --- |
| `config/` | 人可编辑的配置与模板 | 人 | 会（启动时读配置） | 是（默认值与模板） |
| **`data/`** | 程序运行需要的状态、数据库、缓存、凭证 | **程序** | **会**（反复读 / 下次启动读） | **默认否**（本机/本用户状态） |
| `outputs/` | **程序的正式产出**（含需留档但用户不主动取的结果文件） | 程序 | 一般不回读 | 否 |
| `temp/` | 用完即删的实验区；程序写出后**不再回读**的一次性中间产物 | 人 / AI / 程序 | **不会** | 否 |

> **边界一句话**：**人写的、能手工编辑的默认值 → `config/`；程序自己写、只对本机或本用户
> 有意义的运行状态 → `data/`。**
> 一个功能同时需要两者很常见：`config/settings.toml` 存用户设定的默认值，
> `data/state.json` 存程序跑出来的当前状态。**不要把两者混在一个目录里。**

### 4.1 `data/` 与 `temp/` 的分界（最容易放错）

程序产生的中间产物**不都是一次性的**，所以判据**不是「临时不临时」，而是「程序还会不会自己回读」**：

| 程序生成之后…… | 去处 |
| --- | --- |
| **本次运行中还会反复读**（cookies、会话 token、登录态、已抓取的页缓存） | **`data/`** |
| **下次启动时还会读**（上次任务记录、断点续跑进度、UI 记忆、索引） | **`data/`** |
| **生成后自己再也不读**（抓完即弃的原始响应、只用于排查的 dump/trace、解压后不再引用的临时文件） | `temp/`（遵循 §5 的 temp 规则） |

> **反例提醒**：爬虫那份 **30 分钟有效的 `cookies.json` 看着「很临时」，但它会被程序反复读回，
> 所以属于 `data/`**——放进 `temp/` 会被「用完即删」的清理想法误删，程序还得重新登录。
> 判据只看**会不会回读**，不看有效期长短。

**为什么这个分界重要**

- `data/` 里的东西**会被回读**，就要当「真数据」对待：写入用原子替换（先写临时文件再
  `os.replace`），别写坏一半；格式变更要能向后兼容或自行迁移。
- `temp/` 里的东西**应当随时可以整目录删掉**，删掉之后程序要能自己重建或重新生成。
  一个文件如果「删了就再也跑不起来」，那它本来就不该在 `temp/`。

**本节判据的适用边界**（别套错地方）

- **`outputs/` 走另一条判据**：**产物 vs 消耗品**——不是「程序会不会回读」，也不是「是否交付」。
  程序的正式产出（**含用户不会主动来取、但也不该随手删的结果文件**）进 `outputs/`；
  与 `temp/` 的分界是「删了要重新构建或重跑」（产物）还是「删了无影响」（消耗品）。
  详见 `13_packaging_and_outputs.md` §3。
- **构建中间产物不属于本节的「一次性产物」**：`outputs/02_build/` 看着不再回读，
  但**构建工具会回读它做增量构建**，所以留在 `outputs/`，**不并入 `temp/`**（2026-09-12 定）。
- **工具自管缓存不进 `data/` 也不进 `temp/`**：`__pycache__`、`.pytest_cache`、`.ruff_cache`、
  `.mypy_cache`、`.venv` 等留在原地，位置与生命周期由工具自己决定。

**典型判定对照**

| 产物 | 会被回读吗 | 去处 |
| --- | --- | --- |
| 爬虫 cookies（30 分钟有效，请求间复用） | 会（反复读） | `data/cookies.json` |
| 登录会话 / API token 缓存 | 会（反复读） | `data/session.json` |
| 断点续爬的进度与已抓 URL 集合 | 会（下次启动读） | `data/progress.json` |
| 上次任务记录 / 窗口位置 / 列宽记忆 | 会（下次启动读） | `data/state.json` |
| 抓完就丢的原始页面 / 响应体 | 不会 | `temp/0003_原始响应/` |
| 只用于排查的 dump、trace、日志明细 | 不会 | `temp/0004_调试dump/` |
| 解压 / 转换后不再引用的中间文件 | 不会 | `temp/0005_解包中间件/` |

**目录约定**

- 用途多于一种时按用途分子目录（`data/cache/`、`data/db/`）；只有单一数据库时
  直接放 `data/app.db` 即可，不必为分层而分层。
- **禁止**把 `*.db` / `*.sqlite3` / `state.json` / `last_task.json` / `history.json` 这类文件
  直接放在项目根目录（这是本条要治的主要毛病）。
- `data/` **默认整体加入 `.gitignore`**（它是本机运行状态，不该随仓库分发）；
  确实需要分发的种子 / 示例数据用 `!data/xxx` 显式放行，并在说明文档或 knowledge 里写明理由。
- 代码里定位数据文件用 `pathlib` 从项目根拼（`PROJECT_ROOT / "data" / "app.db"`），**不硬编码绝对路径**；
  首次运行时**自动创建目录**（`Path("data").mkdir(parents=True, exist_ok=True)`），不假设它已存在。
- 数据库连接串、文件路径这类**指针**放 `config/`；**数据本体**放 `data/`，代码里不要把 db 路径写死。
- 带有效期的状态（cookies、token、缓存）放 `data/`，**过期清理由程序自己负责**（读到即校验 TTL、
  过期就重新获取并覆盖），不要靠人工删文件；这类「有生命周期的状态」仍然是 `data/` 而不是 `temp/`。
- **存量项目**已有散落的数据文件**不强制搬迁**（同 §3，先提方案再动）；
  **新产生的运行时数据一律写入 `data/`**。

## 5. temp/ 使用规则

- `temp/` 下**只能有子目录**，不允许直接在 `temp/` 根下创建任何文件。
- 每个子目录 = 一个**独立工作区**，命名 `NNNN_用途`，例如：

```
temp/
├── 0001_解析接口验证/
│   ├── run_check.py
│   ├── requirements.txt
│   ├── input/
│   └── output/
└── 0002_性能压测/
    ├── bench.py
    └── result.csv
```

- 一个临时实验的**所有东西**（脚本、依赖清单、输入、输出）都放在同一个编号目录里，
  方便一起测试、一起删除。
- **程序生成、且生成后自己不再回读**的一次性中间产物也放这里（判据见 §4.1）：
  同样进 `temp/NNNN_用途/` 子目录，**不在 `temp/` 根下直接建文件**。
  程序要用这类目录时，应当自己创建并可以随时整目录重建。
- `temp/` 里的一切都应当可以随时整目录删掉而不影响运行；
  **会被回读的数据不要放这里，放 `data/`**（把 `data/` 当垃圾桶，或用 `temp/` 存状态，都是本条要治的毛病）。
- 用完即清理；确认无价值后整个子目录删掉（`temp/` 建议加入 `.gitignore`）。

## 6. 大文件（>100MB）

不要复制进 `temp/`，用链接方式：

```powershell
# 硬链接（同一卷内，最快，删除原文件数据仍在）
New-Item -ItemType HardLink -Path "temp\0003_大文件实验\data.bin" -Target "D:\data\big.bin"

# 软链接 / 目录联接（可跨卷，可指向目录）
New-Item -ItemType SymbolicLink -Path "temp\0003_大文件实验\dataset" -Target "D:\datasets\xxx"
cmd /c mklink /J "temp\0003_大文件实验\dataset" "D:\datasets\xxx"
```

- 同卷优先硬链接，跨卷或指向目录用符号链接 / junction。
- 管理员权限/开发者模式可能才允许创建符号链接，失败时退回 junction 或硬链接。
- **绝不**把大文件提交进 git（见 `05`）。

## 7. 命名与编码

- 目录/文件名用英文小写 + 下划线（`data_loader.py`）；
  **文档与临时目录**可用中文（`0001_解析接口验证/`），但源码标识符必须是英文。
- 所有文本文件统一 **UTF-8**；脚本读写文件显式指定 `encoding="utf-8"`。
- 路径用 `pathlib.Path`，不要硬编码盘符或分隔符。

## 8. 清理清单（任务收尾时）

- [ ] `temp/` 里本次新建的子目录：还要用 → 保留；用完 → 删除
- [ ] 根目录没有新增杂物
- [ ] 本次新增/修改的配置文件都在 `config/` 下，根目录与 `src/` 下没有散落的 `*.toml` / `*.json` / `*.ini`
- [ ] 程序新产生的数据（数据库、状态文件、缓存、cookies）都写在 `data/` 下，根目录没有 `*.db` / `state.json` 之类
- [ ] **回读判据核对过**：程序生成后还会回读的（含带有效期的 cookies/token）在 `data/`；
  生成后不再回读的一次性中间产物在 `temp/NNNN_xxx/` 下——两者没有混放
- [ ] `data/` 已加入 `.gitignore`；`config/` 里的真实密钥没有被 `git add`（只提交 `*.example.*` 模板）
- [ ] 没有把输出文件、日志、缓存误提交（检查 `git status`）
- [ ] 大文件只以链接形式存在
