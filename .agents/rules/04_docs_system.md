# 04 · 文档体系（.agents/docs）

新建、编号、归档、引用文档前读本文件。

## 1. 五个分类的定位

| 分类 | 放什么 | **不**放什么 |
| --- | --- | --- |
| `knowledge/` | 行业/领域知识、软件知识、**为什么这样设计**、常改点怎么改、参数怎么调、已跑通的完整流程、软件架构、如何测试、开发流程 | 常规功能改动的流水账；**项目全貌总览**（那是 `.agents/ARCHITECTURE.md` 的活，见 rules/15） |
| `questions/` | 一个错误/缺陷的**完整复盘**：现象、复现、根因、修复过程、如何避免再犯 | 正常的功能修改 |
| `explore/` | 外部调研、方案对比、可行性验证报告 | 已拍板并落地的实现细节（那属于 knowledge） |
| `todo/` | 排队中的任务：背景、目标、状态、关联 checkpoint；**`todo/README.md` 是任务索引与调度表** | 已完成的任务（移入 `_archive/` **并从索引删行**，见 rules/07 §2） |
| `checkpoint/` | 长任务进度快照，用于中断后恢复 | 小任务的临时笔记 |

### 判定口诀

- **knowledge 的门槛**："换一个人（或换一个 AI 会话）来接手，会不会因为不知道这件事而做错或重复踩坑？"
  会 → 写；不会 → **不写**。只放精华，宁缺毋滥。
- **knowledge 的长度纪律（第 34 条，check 会预警）**：单份 ≤ **150 行**——knowledge 是
  按需加载的，超长就等于"大文件全读"。超了不是删，而是**外移**：细节拆成新文档或挪去
  代码注释，原文只留结论 + 指针。
- **questions 的门槛**："这是一个 bug/错误吗？" 是 → 写；只是需求变更 → 不写。
- **explore 的门槛**："这是我让你去调研/查证的东西吗？" 是 → 写。

## 2. 编号规则

> **两个例外**（不编号、不归档、原地更新，不属于本节编号体系）：
>
> 1. `.agents/ARCHITECTURE.md` —— 架构总览，维护纪律见 `15_architecture_doc.md`；
> 2. `.agents/docs/todo/README.md` —— **任务索引与调度表**，维护纪律见 `07_task_tracking.md` §2
>    （增删/激活/排序一律用 `.agents/tools/taskmgr.py`，不要手改表格）。
>
> 除此之外，`docs/` 下一切 `.md` 都要 `NNNN_*.md` 编号。

- 文件名格式：`NNNN_标题.md`，4 位数字补零，例如 `0001_数据加载流程.md`。
- **编号在每个分类目录内独立递增**（`knowledge/` 和 `todo/` 各有一套 0001）。
- 编号取当前分类（含子目录）最大值 + 1，**不复用**已归档文档的编号。
- 用 `python .agents/tools/newdoc.py new <category> <标题> [--sub 子分类]` 自动分配编号，不要手编号。

## 3. 子分类

- 每个父分类下**最多再分一层**，例如：
  - `knowledge/software/` — 软件工程、本项目架构、工具链
  - `knowledge/domain/` — 行业/业务领域知识
  - （可按需增加子分类，如 `knowledge/thirdparty/`）
- **禁止更深嵌套**：不允许 `knowledge/software/db/schema/`。
- 子分类按需增加，不预先铺满空目录。

## 4. 归档规则

- 每个**父分类**下都有一个 `_archive/` 目录（如 `knowledge/_archive/`、`todo/_archive/`）。
- 归档对象：
  - **todo** 完成/废弃 → 用 `.agents/tools/taskmgr.py done|drop <编号>`：
    补全完成记录 → 状态改 `已完成`/`已废弃` → 移入 `todo/_archive/` →
    **同步从 `todo/README.md` 索引里删掉该行**（只归档不出表 = 违规）
  - **explore** 被确认可行 → 归档 + 同时创建对应 todo；被否决 → 归档并注明否决原因
  - **knowledge** 过时（架构已变、方案已弃）→ 移入 `knowledge/_archive/`
  - **questions** 已修复且长期未复发 → 可移入 `questions/_archive/`
  - **checkpoint** 对应任务已收尾 → 移入 `checkpoint/_archive/`
- 归档时**在文首补一行**：
  ```
  > 归档时间: 2026-09-01  |  归档原因: 任务已完成  |  关联文档: todo/0007_xxx.md
  ```
- 归档文档**不再被任何文件引用**；归档后必须同步删除/更新指向它的引用（用 `check` 校验）。

## 5. 各类文档模板

### knowledge

```markdown
# 0001_标题

> 分类: knowledge/software  |  创建: 2026-09-01  |  适用范围: <哪些模块/场景>
> 关键词: <便于检索的几个词>

## 背景 / 结论
（先给结论，再给细节——AI 读文档时最需要的是"我该怎么做"）

## 细节

## 常见改动点
- 想改 X → 改 `<文件>:<行/函数>`，注意 Y

## 参考
- 关联代码：`src/...`
```

### questions

```markdown
# 0003_标题（现象的一句话）

> 分类: questions  |  发现: 2026-09-01  |  状态: 已修复  |  严重级别: 高/中/低

## 现象
（报错原文、复现步骤、影响面）

## 排查过程
1. ...

## 根本原因
（不是"改了哪行"，而是"为什么会这样"）

## 修复方案
（改了什么、为什么这样改、相关 commit）

## 如何避免再犯
（检查清单 / 约定 / 需要补的测试）
```

### todo

```markdown
# 0005_标题

> 状态: 排队 / 进行中 / 已完成 / 已废弃  |  创建: 2026-09-01  |  完成: -
> 优先级: 高/中/低  |  关联 checkpoint: checkpoint/0002_xxx.md

## 背景
## 目标（验收标准，要可判定）
## 现状 / 阻塞
## 完成记录
```

### checkpoint

```markdown
# 0002_标题

> 任务: todo/0005_xxx.md  |  更新: 2026-09-01  |  进度: 3/7
> 最近 commit: a1b2c3d

## 已完成
## 进行中（下一步从这里继续）
## 待办
## 关键决策与上下文（恢复任务必须知道的信息）
```

### explore

```markdown
# 0001_标题

> 分类: explore  |  日期: 2026-09-01  |  结论: 可行 / 不可行 / 待定

## 问题
## 调研范围与方法
## 候选方案对比
## 结论与建议
## 后续（若被确认 → 建 todo）
```

## 6. 引用纪律

- 引用一律使用**相对项目根**的路径，例如 `.agents/docs/knowledge/software/0001_xxx.md`。
- 在 AGENTS.md 或 rules 中引用文档时，确保文档存在；移动/归档后**必须同步更新引用**。
- 校验命令：`python .agents/tools/newdoc.py check --root <项目根>`
  （检查编号重复、引用断链、空 `_archive`）。

## 7. 已有文件的整理（规范化存量文档）

规范化项目时若发现已有 `README.md`、`docs/`、 issue 复盘、`TODO.md`、`.cursor/rules` 等：

1. 先**只读扫描**，输出迁移计划表（哪→哪），给用户确认；
2. 迁移后**逐个修正旧引用**（相对链接、文档内提到的路径）；
3. 原位置的旧文件在确认后移入对应 `_archive/` 或删除，**不要静默删除**；
4. 内容重复的多份文档合并为一份，保留最完整的版本并注明来源。
